# Full chat-run worldwide veterinary oncology trial audit (2026-10-17)

This is an **independent on-demand procedure** for a single coherent, full audit in an ordinary chat. It does not replace or silently alter the scheduled 03:00 daily audit, 22:00 care work, or European country controller. Based on the September 30 method in `data/DAILY_AUDIT_ALGORITHM.md` at `761307fc3fd7`, with subsequent evidence, safety, diagnosis-matcher and production checks retained. Follow AGENTS.md and PROJECT_OPERATIONS.md. User standing authorization covers confirmed data/technical changes without confirmation.

## Start and atomic outputs
1. Read remote-main canonical catalog, source inventory, audit state and unresolved receipts; freeze record IDs and previous dates/SHA before work. Create a unique audit directory and durable ledger with source IDs, trial IDs, search candidates and evidence. Maintain one run_id and ONE final user-facing report, even if many requests/commits are required. Interim conversation updates must not misrepresent partial results as a final report.
2. Sweep **every currently registered official source** (113 at adoption, not a fixed cap), including each available official master, oncology subindex and appropriate study-level URLs, plus mandatory registries, sponsors and multicenter site rosters. Check full candidate inventory against canonical records. Read primary protocols for every new, changed, ambiguous, overdue, status/site/funding-conflicted or previously incomplete current trial. Perform independent eligibility evidence review for due and outstanding public trials (40 at adoption). Source visited ≠ study verified. Never copy a roster from a prior date and call it today's verification.
3. Search the **entire world**, all 12 configured regions, in English and local languages, using two passes: current/undated/background and recent with ≥7-day overlap. Include trial indexes, university centers, hospitals, CRO/sponsors, PI laboratories, foundations, registries, trial PDFs, and newly indexed old pages. Log actual queries/results and follow every plausible therapy lead to primary/current study evidence. No fixed small query quota and no arbitrary candidate cap. Absence of candidates from a small sample cannot support 'worldwide zero'.
4. Reconcile each study by protocol identity (intervention, disease/cohort, center/sponsor, stage, access), eligibility including specific and excluded tumors/prior therapy, dates, status, site roster, recruitment contact, owner costs, and treated species. Semantic dedupe against **the complete effective canonical database**. Track candidate decisions VERIFIED_NEW / EXISTING_VERIFIED / UPDATE_CONFIRMED / CLOSED_CONFIRMED / NOT_INTERVENTIONAL_TREATMENT / DUPLICATE / EVIDENCE_CONFLICT / PENDING_PRIMARY / INACCESSIBLE. Do not confuse diagnostics or observation with treatment, or automatically discard valid treatment-access programs.
5. Technical access failures: attempt alternate *permitted public* routes such as official PDF, PI pages, sponsor pages, recognized registries, indexed documents and alternate master URLs. CAPTCHA/403 on one URL does not end research. Do not bypass explicit access restrictions, credential gates or private protections. Record precise actual failure and evidence gap. Do not demand owner manually solve a CAPTCHA or contact centers. No needless repeated failed calls.
6. For verified updates, change the minimal canonical/inventory fields, independently test source-derived positive/negative/unknown matcher cases and exact eligibility boundaries, run sanitation/schema/source/dedupe/matcher regression/build tests. Publish validated confirmed data and technical changes to main automatically; verify commit/deployment/production content. Medical/editorial ambiguity, disputed duplicates/status and owner-facing copy/UI need user input, without blocking unrelated verified changes.
7. Completion requires TWO independent gates: (A) current public study and due protocol verification, with item-level outcomes; (B) all inventory sources, all twelve regions, both global rounds, every lead with disposition. Strict receipt must distinguish executor unfinished from source inaccessible. If interrupted, persist exact pending IDs and continue from that ledger without restarting; never claim COMPLETE for a partially executed run.
8. Deliver **one consolidated Russian report in chat**: NEW (protocol identities/links), UPDATED field-level before/after, CLOSED/HIDDEN, NEW SOURCES, world regions/queries/coverage, verified existing trials and unresolved IDs, canonical counts before/after, independent matcher validation, GitHub commit/deploy/live proof, actual source timestamps, unresolved clinical questions, explicit COMPLETE/INCOMPLETE and why. No file-only report, no optimistic '0 new' without full evidence. All workers must return their individual receipts before aggregated acceptance.

## Execution limitations
An ordinary chat may lack the full Work shell/runtime and cannot truthfully claim unseen background progress. Use available GitHub connector and browser/web tools, preserving exact URLs and access failures. Continue as far as possible in the active turn, report uncompleted scope explicitly; never manufacture runtime, approvals, production checks or an exhaustive audit.
